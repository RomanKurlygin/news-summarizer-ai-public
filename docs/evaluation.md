# Оценка суммаризации

`POST /api/v1/evaluate` запускает одну конфигурацию на 1–4 заранее отложенных новостях. Он принимает настройки суммаризации и массив `test_ids` из исходных ID XSum или UUID. Если массив опущен, используется первая запись подготовленного контрольного файла `HOLDOUT_PATH`. Для сравнения конфигураций явно передавайте одинаковые ID и режим. Повтор одной новости через исходный ID и UUID отклоняется.

```json
{
  "provider": "ollama",
  "model": "qwen2.5:1.5b",
  "mode": "baseline",
  "test_ids": ["34227252"]
}
```

Каждый пример проходит через обычный сервис суммаризации с исходным текстом новости. Эталон подключается лишь в паре для вычисления метрик. RAG сверяет хэши отложенного набора, поэтому эти пары отсутствуют в поисковых индексах, а отобранная подсказка содержит только форму учебного резюме. API возвращает оценки, фактическую модель, параметры, идентификаторы примеров и запросов, статусы, размер выборки, число оценённых примеров и время в секундах. Неудачные генерации видны в `items` с ошибкой и отсутствующими метриками. Если все генерации завершились ошибкой, возвращается HTTP-ошибка. `GET /api/v1/evaluate/history?limit=20&offset=0` возвращает сохранённые результаты пользователя. Администратору доступны оценки всех владельцев.

## Метрики

Перед расчётом применяется Unicode NFKC и объединяются последовательности пробелов. Если одна сторона пуста, все метрики пары равны 0. Итог по набору — арифметическое среднее посэмпловых значений по успешно сгенерированным примерам, включая тексты со статусом `needs_review`, чтобы не скрывать ошибки генерации. Сводная оценка с частичным покрытием интерпретируется вместе с `scored_count` и `sample_size`.

- **BLEU-1 и BLEU-2.** SacreBLEU с токенизацией `13a` и нижним регистром. Для одного резюме берутся модифицированные точности по совпавшим n-граммам и их геометрическое среднее, умноженное на штраф за краткость `min(1, exp(1 − len(ref)/len(hyp)))`. Sentence-level BLEU использует `smooth_method=exp` для нулевых совпадений и `effective_order=True` для коротких текстов. Версия BLEU-2 для однотокенного текста учитывает только униграммы. [SacreBLEU](https://github.com/mjpost/sacrebleu)
- **ROUGE-1, ROUGE-2 и ROUGE-L.** `rouge-score` возвращает F1 по совпавшим униграммам, биграммам и длине наибольшей общей подпоследовательности. Общий Unicode-токенизатор выделяет буквы и цифры после приведения регистра. Стемминг не применяется. ROUGE-2 для одного токена равен 0. [ROUGE](https://github.com/google-research/google-research/tree/master/rouge)
- **METEOR.** NLTK сопоставляет токены по совпадению, английской основе Porter и синонимам WordNet. Взвешенное гармоническое среднее точности и полноты уменьшается за фрагментацию совпавших токенов. Настройки ориентированы на англоязычный XSum. [NLTK METEOR](https://www.nltk.org/api/nltk.translate.meteor_score.html)
- **chrF и chrF++.** SacreBLEU считает F2 по точности и полноте символьных n-грамм порядков 1–6. chrF++ включает словесные униграммы и биграммы. Текст здесь сохраняет регистр. [SacreBLEU](https://github.com/mjpost/sacrebleu)
- **BERTScore.** Библиотека `bert-score` сопоставляет нормализованные контекстные эмбеддинги токенов по максимальному косинусному сходству. Возвращаются точность, полнота и их гармоническое среднее F1. Используется последний, 12-й слой `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` с ревизией `e8f8c211226b894fcb81acc59f3b34ba3efd5f42`, быстрым токенизатором, на CPU, без IDF и пересчёта по baseline. Контекстные эмбеддинги вычисляются для токенов. Пуллинг SentenceTransformers для этой метрики не применяется. [Реализация BERTScore](https://github.com/Tiiiger/bert_score) · [Ревизия MiniLM](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2/tree/e8f8c211226b894fcb81acc59f3b34ba3efd5f42)
- **Exact Match.** Возвращает 1 при равенстве нормализованных строк без учёта регистра и 0 иначе. Пунктуация сохраняется. Для свободного пересказа это вспомогательное измерение.

BLEU и chrF делятся на 100. Лексические метрики и Exact Match публикуются в диапазоне 0–1. BERTScore публикуется на собственной косинусной шкале без пересчёта. Версии четырёх библиотек и ревизия модели сохраняются в `metric_metadata`. Высокое сходство с эталоном может сочетаться с неверным числом, именем или причинной связью. Фактические проверки и их статусы оцениваются отдельно.

## Установка и тесты

```powershell
poetry install --with rag,evaluation
poetry run python -m nltk.downloader -d .cache/nltk wordnet
poetry run pytest tests/unit/test_metrics_calculator.py tests/integration/test_stage12_api.py
```

BERTScore использует закреплённый локальный снимок в `EMBEDDING_CACHE_DIR`. Если его ещё нет, загрузите снимок один раз перед запуском сервера.

```powershell
poetry run python -c "from huggingface_hub import snapshot_download; from backend.core.config import Settings; from backend.evaluation.metrics_calculator import BERT_MODEL, BERT_REVISION; snapshot_download(BERT_MODEL, revision=BERT_REVISION, cache_dir=Settings().embedding_cache_dir, allow_patterns=['config.json','model.safetensors','tokenizer.json','tokenizer_config.json','special_tokens_map.json'])"
```

Для сетевой проверки установите Ollama и подготовьте локальные индексы, затем задайте `RUN_LIVE_STAGE12=1` и запустите `poetry run pytest tests/integration/test_live_stage12_api.py`. Метод расчёта остаётся одинаковым на Windows и macOS.

Для фиксированных выборок 20, 50 и 100 используйте экспериментальный CLI либо `POST /api/v1/evaluate/batch`. Они вызывают тот же калькулятор и сохраняют оценки, таймауты и вердикты по каждой новости. Сводка сохраняется под ID эксперимента. [Протокол и команды](./experiments.md)
