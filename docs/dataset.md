# Корпус новостей и справочник

## Источник и права

Для первой версии используется англоязычный XSum. В каждой строке `document` содержит новость BBC, `summary` — однопредложенческое эталонное резюме, `id` — идентификатор BBC. Источник предоставляет официальные разделы train, validation и test. [Карточка XSum](https://huggingface.co/datasets/EdinburghNLP/xsum) · [Статья авторов](https://aclanthology.org/D18-1206/)

У корпуса в карточке указана лицензия `unknown`. MIT в репозитории авторов распространяется на файлы репозитория. Для перераспространения журналистских текстов BBC потребуется отдельно подтвердить права. Корпус используется локально для учебной проверки. Исходные снимки, экспорты CSV/JSON и SQLite с текстами исключены из Git. [Метаданные лицензии XSum](https://huggingface.co/datasets/EdinburghNLP/xsum/blob/7d4d486c2f8ef850b1a11aead99b894ff3dd7da9/README.md) · [Репозиторий авторов](https://github.com/EdinburghNLP/XSum) · [Условия BBC](https://downloads.bbc.co.uk/usingthebbc/bbc_terms_of_use_19September2022english.pdf)

Резервный CNN/Daily Mail предоставляет `article`, `highlights` и `id`. Карточка указывает Apache-2.0 для версии 1.0.0. Для другой версии и распространения материалов издателей условия следует проверить отдельно. У highlights часто несколько предложений. Импорт этих полей поддерживается из локального файла. [Карточка CNN/Daily Mail](https://huggingface.co/datasets/abisee/cnn_dailymail)

## Подготовка и разбиение

- `generate_data` получает страницы Hugging Face Dataset Viewer по HTTPS. По умолчанию читаются первые 1250 строк официального train и 300 строк официального test. Суммарный предел декодированных ответов — 32 МиБ. Ревизия Hub проверяется до и после загрузки. API строк обслуживает текущую ревизию, поэтому для точного повтора используется сохранённый снимок. Манифест хранит ревизию, диапазоны строк, объём ответов, параметры и SHA-256 снимка. `verify_dataset --check-source` повторно сверяет строки с API. [Hugging Face Dataset Viewer API](https://huggingface.co/docs/dataset-viewer/rows)
- Очистка приводит Unicode к NFKC, удаляет управляющие символы, сводит последовательности пробелов к одному и отбрасывает пустые тексты, пустые резюме, строки без происхождения и пары с одинаковыми текстом и резюме. Для сравнения применяется `casefold`. Дубликат определяется по UUID либо совпадению нормализованного текста или резюме. Сравнение поперечное и выявляет также совпадение резюме из одного набора с текстом новости из другого.
- При наличии официальных разделов все полученные тестовые кандидаты резервируются до отбора train, включая те, что не войдут в итоговые 200. Раздел validation пропускается. В локальном наборе без `split` после очистки, перемешивания с seed `42` и дедупликации первые записи отводятся в test, следующие в train. Смешанный файл с частично заполненным `split` отклоняется.
- `data/test/evaluation_ids.json` фиксирует вложенные префиксы тестового порядка. Размеры 20, 50 и 100 используют одни и те же зафиксированные UUID в будущих прогонах. Для индексирования, справочника, few-shot и обучающих правок HITL следует использовать train. Импорт блокируется, если существующая база знаний уже содержит совпадение с test.

Отбор ограничен первыми страницами разделов XSum. Источник содержит англоязычные новости одного издателя. Значение `general` используется для XSum, поскольку категории отсутствуют в его схеме. Проверка точного нормализованного текста не измеряет смысловую близость публикаций. Эталонные тексты и категории справочника могут требовать ручной проверки.

## Формат файлов

- `data/import/news_train.{json,csv}` и `data/test/news_test.{json,csv}` имеют общую схему `id`, `source_text`, `target_text`, `language`, `category`, `source_dataset`, `source_document_id`, `source_url`, `split`. UUID v5 строится из имени источника и его идентификатора. При отсутствии внешнего ID используется SHA-256 нормализованного текста. У XSum ссылка ведёт на строку Dataset Viewer.
- `data/import/glossary.{json,csv}` содержит `id`, `term`, `definition`, `category`, `language`, `aliases`, `source`, `review_required`. В CSV поля `source` и `aliases` записаны в JSON. В `source` хранятся UUID учебной статьи, правило извлечения и число учебных документов с термином.
- `data/raw/news_candidates.json` содержит снимок до очистки. `data/import/manifest.json` описывает воспроизведение. Для локального ввода проверка сравнивает результат со снимком. Достоверность заявленного внешнего происхождения файла зависит от его поставщика.

## Справочник

Правила обрабатывают только `source_text` из train. Имена ищутся рядом с титулами, организации по маркерам названия, географические названия по контексту и тематические термины по словарю шаблонов. Ранжирование учитывает качество признака, число документов и нормализованный ключ. В подборке резервируется место для представленных категорий. Пары «полное название (аббревиатура)» дают alias, если буквы совпадают с инициалами слов.

В `definition` хранится дословный контекст, который можно проверить по `source.news_id`. Он может содержать упоминание без словарного определения. Неоднозначные эвристики выставляют `review_required=true`. Отсутствие флага означает выполнение более строгого правила. Ручная верификация категорий в этом прогоне не проводилась.

Обработка текстов и поле языка поддерживают Unicode, включая русский. Шаблоны справочника рассчитаны на английский. Для русского справочника потребуются соответствующие правила или проверенный лексический источник.

## Запуск

Из корня проекта выполните подготовку и проверку файлов.

```text
poetry run python -m scripts.generate_data --seed 42
poetry run python -m scripts.build_glossary
poetry run python -m scripts.verify_dataset
```

Для точного повтора из локального снимка XSum укажите `--snapshot`. Аргумент `--input` принимает CSV, массив объектов JSON либо TXT/TSV с табличным заголовком. Распознаются `document/summary/id` и `article/highlights/id`. Через `--source-dataset` указывается фактический поставщик, если его нет в строках. `--train-count`, `--test-count`, `--language`, `--seed` и `--output-dir` задают размеры, язык, порядок и каталог вывода. Для нестандартного каталога передавайте тот же путь через `--data-dir` в остальных командах.

```text
poetry run python -m scripts.generate_data --snapshot data/raw/news_candidates.json --source-dataset EdinburghNLP/xsum --seed 42
poetry run python -m scripts.generate_data --input local_news.csv --output-dir data/raw/local --source-dataset dataset-name --language en --train-count 1000 --test-count 200
```

Создайте отдельную SQLite БД. В Windows PowerShell задайте URL следующим образом.

```powershell
$env:DATABASE_URL = 'sqlite+aiosqlite:///data/corpus-demo.sqlite3'
```

На macOS используйте `export DATABASE_URL='sqlite+aiosqlite:///data/corpus-demo.sqlite3'`. Затем запустите миграции, импорт обоих форматов и проверку повторения.

```text
poetry run alembic upgrade head
poetry run python -m scripts.import_data
poetry run python -m scripts.import_data --format csv
poetry run python -m scripts.verify_dataset --check-db --check-source
```

`import_data` записывает новости и справочник одной транзакцией. Повторный импорт пропускает совпадения и сохраняет существующие записи. Конфликт ID с другим содержимым отменяет транзакцию. `verify_dataset --check-db` читает БД и проверяет, что следующий импорт не добавит строк. `--check-source` используется только для онлайн-сверки снимка XSum. Для PostgreSQL применяется прежняя схема URL `postgresql+asyncpg://…` и та же миграция `0002`. Фактический импорт этапа выполнен в SQLite.

```text
poetry run pytest tests/unit/test_corpus_data.py tests/integration/test_corpus_import.py
```

Обычный запуск тестов использует локальные фикстуры, SQLite и подмену транспортного слоя HTTPX.

## Проверенный прогон

На ревизии `7d4d486c2f8ef850b1a11aead99b894ff3dd7da9` получено 1550 кандидатов XSum. Объём декодированных HTTP-ответов составил 3 761 058 байт. Отброшены одна некорректная строка и два дубля. SHA-256 локального снимка — `40a904addf41111ba5223ce4020ad084e237ae4789eecb45905fefad174de904`. Онлайн-сверка подтвердила совпадение снимка с XSum.

В `data/corpus-stage9-verified.sqlite3` импортированы 1000 учебных пар и 500 записей справочника. Справочник включает 50 имён, 304 записи организаций, 94 географических названия и 52 тематических термина. В 50 записях найдены варианты написания. Повторный импорт из CSV пропустил все 1500 записей. Отдельные 200 тестовых пар и вложенные выборки 20/50/100 сохранены на диске. Совпадений ID и нормализованных текстов между train и test — 0, совпадений тестовых пар с базой знаний — 0.
