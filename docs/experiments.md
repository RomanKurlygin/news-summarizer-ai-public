# Воспроизводимая оценка на XSum

## Режимы

- `baseline` вызывает только Summarizer.
- `+dict` добавляет к Summarizer проверенные определения и варианты написания для терминов из исходной новости. Контекст ограничен шестью записями и 800 символами. Снимок фиксируется на весь эксперимент.
- `+rag` добавляет к Summarizer гибридный поиск BM25 и Qdrant. Из ближайшей учебной пары в промпт передаётся только подсказка о форме резюме.
- `+agents` выполняет Summarizer, Validator, Critic и при необходимости Editor через Supervisor. Словарь и индекс не используются.
- `+ensemble` выполняет два прогона `+agents` для модели-кандидата с температурами Summarizer 0 и 0,2. Общий судья по умолчанию — Ollama `qwen2.5:1.5b`. Выбор идёт только среди результатов `verified` по баллу Critic. При равенстве выбирается первый вариант. При отсутствии принятого варианта фиксируется `no_verified_candidate`. Отчёт сохраняет вердикты и ID запросов обоих кандидатов.

`full` остаётся прикладным режимом со справочником, RAG и агентами. Эксперимент может включать `full` как дополнительную конфигурацию. Отсутствие релевантного термина или RAG-результата даёт пустой контекст. Ошибка настроенного компонента видна в результате. Неподдерживаемое имя режима отклоняется.

## Протокол и результаты

Выборки 20, 50 и 100 берутся из `data/test/evaluation_ids.json`, подготовленного из XSum с seed 42. Перед запуском проверяются вложенность, порядок и уникальность UUID и раздел `test`. Сохранение всех ID позволяет повторить сравнение на одинаковых входах. RAG сверяет хэши и ID всего контрольного набора при открытии снимка. Словарь фильтруется по контрольным текстам и эталонам. Эталон передаётся только калькулятору метрик как вторая часть пары.

Протокол фиксирует параметры и seed генерации, SHA-256 промптов и реализации, хэш контрольного корпуса, снимки словаря и индексов, digest Ollama, ревизии Transformers и BERTScore и версии библиотек метрик. Fallback между провайдерами отключён. Повторный запуск незавершённого эксперимента проверяет совпадение протокола и продолжает с первого незаписанного примера. Терминальные ошибки уже записанных примеров остаются видимыми. Смена модели, промпта, индекса или корпуса требует нового эксперимента.

Сводка показывает долю успешных обработок и причины ошибок, в том числе таймауты. Метрики усредняются по примерам с полученным текстом. `evaluation_time` складывает длительности генераций, включая RAG, проверки и правки. Командный отчёт `invocation_seconds` включает также подготовку и расчёт метрик. Доли замечаний Validator считаются среди реально проверенных вариантов, включая оба кандидата ансамбля. Средний балл Critic использует финальные оценки кандидатов, полученные без fallback. Если проверки не вызывались, указанные показатели равны `null`.

Для завершённого сравнения одного размера и общих ID основной показатель — ROUGE-L, дополнительный — BERTScore F1. Победитель определяется только между двумя или более полностью оценёнными конфигурациями. Неполные результаты остаются в сводке с покрытием, а замечания о фактах показаны отдельно от сходства с эталоном. Сравнение на двух новостях служит диагностикой. [Шкалы и формулы](./evaluation.md)

## CLI

Сначала установите зависимости с группами `rag,evaluation`, подготовьте модели, WordNet и индексы. Укажите свою `DATABASE_URL` и выполните миграции. Для `+dict` и `full` используется проверенный справочник в той же БД. Команды из корня проекта работают в PowerShell и терминале macOS.

```text
poetry install --with rag,evaluation
poetry run alembic upgrade head
poetry run python -m scripts.run_eval --models ollama=qwen2.5:1.5b transformers=Qwen/Qwen2.5-0.5B-Instruct --modes baseline --sample-sizes 20 --diagnostic 2
poetry run python -m scripts.run_eval --models qwen2.5:1.5b --provider ollama --modes baseline --sample-sizes 20 --seed 42
poetry run python -m scripts.run_eval --resume <experiment_id>
```

Для полной матрицы выполните команду после проверки доступного времени. По умолчанию обрабатывается по одному примеру. Значение `--parallelism 2` позволяет запустить два. `--timeout` ограничивает одну агентную цепочку в секундах. Для ансамбля лимит применяется к каждому кандидату.

```text
poetry run python -m scripts.run_eval --models ollama=qwen2.5:1.5b transformers=Qwen/Qwen2.5-0.5B-Instruct --modes baseline +dict +rag +agents +ensemble --sample-sizes 20 50 100 --seed 42 --parallelism 1 --timeout 120 --output-dir data/indexes/experiments
```

CLI печатает `experiment_id` перед началом. По умолчанию `data/indexes/experiments/<experiment_id>.json` содержит протокол, все результаты по ID и сравнения, а одноимённый CSV — сводку с одной строкой на конфигурацию и размер. Для продолжения используется та же база данных и идентификатор. JSON и CSV подменяются атомарно. Тексты контрольного корпуса и эталоны не экспортируются. CSV с UTF-8 BOM можно импортировать в Excel, указав текстовый тип столбца `mode`.

## Redis и Celery

API публикует в брокер UUID записи эксперимента. `evaluate_model_task` выполняет одну конфигурацию, `compare_models_task` выполняет несколько через тот же runner. Worker открывает отдельные асинхронные ресурсы для задачи и сохраняет статусы, прогресс и результаты в SQL. Повторная доставка завершённой задачи возвращается без вычислений. Аренда и контрольные точки защищают результаты от дублей и конкурентной записи. При внезапном завершении процесса незаписанный пример может снова вызвать провайдер.

Минимальная конфигурация включает Redis 7 и Linux worker. Подготовьте SQLite или PostgreSQL и примените миграции до запуска. Для SQLite используйте один и тот же файл из каталога `data` на хосте и в контейнере. По умолчанию worker открывает `data/experiments.sqlite3`. Альтернативный URL задаётся через `WORKER_DATABASE_URL`. Redis доступен хосту на `127.0.0.1:6379`, для приложения задайте `CELERY_BROKER_URL=redis://127.0.0.1:6379/1`. У Ollama должен быть доступный контейнеру адрес. По умолчанию это `host.docker.internal:11434`. Путь переопределяется через `WORKER_OLLAMA_BASE_URL`. При одновременной работе API и worker с поиском используйте Qdrant Server, чтобы процессы не делили эксклюзивную блокировку одного каталога Qdrant local.

```text
docker compose -f infrastructure/compose.experiments.yml up -d --build
docker compose -f infrastructure/compose.experiments.yml exec redis redis-cli ping
docker compose -f infrastructure/compose.experiments.yml logs worker
```

В Linux или WSL2 с отдельно доступным Redis worker запускается через `poetry run celery -A backend.worker.celery_app:app worker --pool=solo --concurrency=1 --loglevel=INFO`. На машине проверки Docker Desktop и запущенный Linux-дистрибутив WSL2 отсутствовали. Проверены сериализация и доставка обеих задач настоящему тестовому worker через брокер в памяти. Обмен через Redis 7 с Linux worker ожидает проверки. [Celery и Redis](https://docs.celeryq.dev/en/stable/getting-started/backends-and-brokers/redis.html) · [Поддерживаемые платформы Celery](https://docs.celeryq.dev/en/stable/faq.html)

### Ручная проверка

Для пяти одинаковых статей сверены итоговые резюме всех четырёх режимов с исходной новостью. Проверены участники, места, величины, события, статус утверждений и сохранение главных сведений. Ошибкой считалось существенное противоречие источнику или факт, который источник не подтверждает. Пропуски отмечены отдельно. Ручная оценка относится к этому поднабору.

- **37079851.** `baseline` и `+agents` ввели Криса Фрума и отнесли трековый скретч к Tour de France. Validator пометил имя. `+dict` добавил Рио и 2016 год, которых нет в тексте, и упустил результаты спортсменов. `+rag` сохранил описанный результат скретча, но повторил его. Во всех режимах выпали третье место Кэвендиша в общем зачёте и рекорд Бекки Джеймс.
- **40617914.** Все варианты ошибочно сделали Hibernian клубом, подписавшим Льюиса. В исходнике из Hibernian уходит Стэнтон. Оба названных сезона отсутствуют в тексте. `+agents` пометил число, а неверного участника трансфера не обнаружил.
- **34227252.** В четырёх резюме не найдено противоречий. Все заменили пятизначную сумму общей формулировкой. `+dict` и `+rag` опустили четверг.
- **36852433.** `baseline`, `+dict` и `+agents` добавили имя Johanna, которого нет в исходнике. `baseline` и `+dict` назвали матч напряжённым, хотя источник описывает уверенную победу. `+agents` вернул `needs_review` по имени. `+rag` сохранил счёт и число эйсов, но опустил соперницу следующего раунда.
- **32197742.** Все четыре режима исказили статус сведений о захоронении жертв протестов. В тексте Human Rights Watch просила проверить эту гипотезу. `+agents` сохранил этот призыв, но одновременно приписал правительству утверждение, что все похороненные погибли на протестах. Validator и Critic пропустили ошибку, результат получил `verified`.

Число резюме с хотя бы одним подтверждённым расхождением с источником из пяти — 4 для `baseline`, 4 для `+dict`, 2 для `+rag` и 4 для `+agents`. Это ручные оценки пяти статей, а не автоматические показатели на 20.

### Что дали компоненты

- **Справочник.** ROUGE-L вырос на 0,0150 (+8,65%), BERTScore F1 снизился на 0,0192 (−3,59%). Среднее время выросло с 0,462 до 0,594 с. Ручная сверка улучшения фактической точности не показала.
- **RAG.** ROUGE-L вырос на 0,0051 (+2,92%), BERTScore F1 снизился на 0,0032 (−0,59%). Среднее время выросло до 1,790 с. В ручной выборке меньше расхождений, но два вида подсказок и пять вручную проверенных статей ограничивают вывод.
- **Агенты.** ROUGE-L вырос на 0,0101 (+5,83%), BERTScore F1 — на 0,0165 (+3,09%). Среднее время выросло до 2,497 с, а среднее число вызовов LLM — с одного до трёх. Агенты выявили неподтверждённые сведения и иногда изменяли текст. Ошибочный `verified` показывает, что статус не заменяет сверку с источником.

На весь новый запуск ушло 110,731 с вместе с подготовкой и метриками. Для исторического baseline это 19,742 с. Набор из 20 статей показывает наблюдаемые различия. Статистическую значимость здесь не проверяли.

### Переиспользование вложенных выборок

Порядок ID подтверждает, что 20 — префикс 50, а 50 — префикс 100. В одном задании размеры обрабатываются по возрастанию. В больший размер переходят вердикт и метрики того же ID для той же пары модель/режим, включая зафиксированную ошибку. Для каждой выборки сохраняются свои агрегаты, `generated_count`, `reused_count` и ID оценки-источника у переиспользованных записей. Продолжение после прерывания восстанавливает эту связь из SQLite. Оно требует совпадения протокола, включая версии модели, промптов, корпуса, компонентов поиска, снимка индекса, справочника и настроек метрик. Архивные запуски сравниваются по ID без переноса в кэш нового задания.

Для одной конфигурации три размера требуют 100 генераций вместо 170, экономия 70 (41,2%). На остаток матрицы двух моделей и пяти режимов приходится 1620 позиций. Если запланировать размеры вместе для каждой конфигурации, потребуется 1000 новых обработок, ориентировочно 1800–4200 вызовов LLM до повторов. Для оставшихся режимов и размеров одной Ollama ориентир — около 18 минут генерации по измеренным средним, плюс метрики и подготовка. На этапе 13.1 размеры 50 и 100, ансамбль и другие модели не запускались.
