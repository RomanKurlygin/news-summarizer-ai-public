# Развёртывание публичной версии

Инструкции настройки секретов и запуска с Windows Ollama приведены в [README](../README.md). Без отдельно подготовленного корпуса init применяет миграции и оставляет доступным baseline.

## Сервисы и данные

Compose описывает PostgreSQL 16, Redis 7, Qdrant, FastAPI, Streamlit, Celery worker и beat, Nginx. В основном варианте используются также Ollama и её инициализация. Вариант compose.windows.yaml переиспользует Ollama на хосте через host.docker.internal и проверяет наличие выбранной модели. Для поддержки !override нужен Docker Compose 2.24.6 или новее.

В исходной конфигурации сервисы проекта используют Compose-имя news-summarizer-public и отдельный тег образа news-summarizer-public:local. Если на компьютере уже есть другая установка этого приложения, задайте отдельное имя через docker compose --project-name и свободный NEWS_PROXY_PORT до создания новых томов.

Корпус из data подключается как bind mount только для чтения. PostgreSQL, Qdrant, снимки RAG, кэши моделей и логи хранятся в отдельных именованных томах. Существующую SQLite копировать для контейнерного запуска не требуется.

## Ollama внутри Compose

Для запуска без хостовой Ollama настройте .env с POSTGRES_PASSWORD и JWT_SECRET_KEY по шаблону .env.example, затем выполните команды ниже.

```text
docker compose config --quiet
docker compose up --build -d
docker compose ps -a
```

В этом варианте ollama-init скачивает qwen2.5:1.5b в том. Первичная загрузка требует интернета и свободного места. Сборка и проверка приложения ранее выполнялись с Windows Ollama; отдельный запуск модели внутри Compose требует проверки в вашей среде.

## Проверка состояния

/healthz проверяет процесс FastAPI, /health — мигрированную БД, /health/dependencies с JWT — связанные сервисы и наличие снимка. Раздел состояния в Streamlit показывает доступные проверки. Наличие файлов индекса отдельно от готовности Qdrant проверяется при открытии снимка.

Через Nginx приложение доступно по http://127.0.0.1:8080, Swagger — по /docs. Порт можно изменить через NEWS_PROXY_PORT. Сетевые настройки и healthchecks приведены непосредственно в Compose. Для остановки используйте docker compose stop с теми же -f и --env-file, что при запуске.

## Корпус и эксперименты

Для полного режима отдельно подготовьте data/import/news_train.json, data/import/glossary.json, data/test/news_test.json и остальные файлы, необходимые скрипту verify_dataset. Подробности в [описании данных](dataset.md). Init проверяет происхождение, импортирует пары и публикует согласованный снимок BM25/Qdrant. Неполный корпус останавливает инициализацию с ошибкой.

Архив сравнения задаётся COMPARISON_ARCHIVE_PATH. В публичной версии нет готового архива и результатов с исходными новостями. Новые результаты можно получить после настройки контрольного набора. Формат и протокол описаны в [документации экспериментов](experiments.md).

## macOS

Установите Docker Desktop для своей архитектуры и Ollama, настройте новые секреты локально и используйте те же Compose-файлы с хостовым адресом host.docker.internal. Проверка на реальном macOS не выполнялась. Доступность сборок и расход памяти на Apple Silicon могут отличаться от Windows x86-64.

Для самостоятельной разработки предусмотрены run.py и Streamlit. Команды установки Python-зависимостей находятся в README. Локальные PowerShell-скрипты используют SQLite и требуют отдельно настроенного окружения разработки.
