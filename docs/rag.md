# Гибридный поиск для суммаризации

## Эмбеддинги и Qdrant

Эмбеддинг — числовой вектор, в котором похожие по смыслу тексты могут оказаться близко друг к другу. SentenceTransformers использует токенизатор и энкодер MiniLM, затем усредняет представления токенов. Модель `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` выдаёт 384 числа и поддерживает, среди прочих языков, русский и английский. В проекте зафиксирована ревизия `e8f8c211226b894fcb81acc59f3b34ba3efd5f42`. Лимит модели равен 128 токенам. У длинной статьи энкодер видит начальный фрагмент, BM25 индексирует весь её текст. [Карточка модели](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2)

Модель загружается при первом вызове и переиспользуется внутри процесса для одинаковых модели, ревизии, устройства и каталога кэша. Загрузка и кодирование выполняются в отдельном потоке. Кодирование идёт пакетами, векторы проверяются на размерность и конечность значений и приводятся к единичной L2-норме. По умолчанию используется CPU. Устройство можно переопределить через `EMBEDDING_DEVICE`, если установленная сборка PyTorch поддерживает это устройство. Веса safetensors занимают около 471 МБ. [PyTorch CPU wheels](https://download.pytorch.org/whl/cpu/torch/)

Qdrant хранит векторы с метрикой cosine и возвращает ближайшие точки. UUID точки совпадает с `KnowledgeBase.id`. В payload хранятся категория, язык, ссылки на источник и нормализованные хеши новости и эталона. UUID связывает результат с парой «новость — эталон» из снимка BM25. Обновление точки по тому же UUID заменяет предыдущий вектор и payload. [Коллекции Qdrant](https://qdrant.tech/documentation/manage-data/collections/)

- **Local mode** — поиск выполняет qdrant-client и хранит данные на диске в папке версии. Имя коллекции по умолчанию `news_knowledge_base`. Каталог одной версии можно открыть только одним процессом одновременно. [Qdrant Python client](https://github.com/qdrant/qdrant-client#local-mode)
- **Qdrant Server** — клиент подключается к `QDRANT_URL` и использует `QDRANT_API_KEY`, если он задан. Имя новой физической коллекции имеет вид `news_knowledge_base__<версия>`. Читающий процесс использует коллекцию из манифеста той же версии, что и BM25. Режим сервера предусмотрен в коде. Прогон этапа выполнен в local mode. [Коллекции Qdrant](https://qdrant.tech/documentation/manage-data/collections/)

## BM25 и RRF

BM25 сопоставляет слова запроса и статьи, учитывая редкость слов, частоту в тексте и длину документа. Токенизация использует Unicode, NFKC и `casefold`. Пунктуация разделяет токены. Стемминг и словарь стоп-слов не применяются. Снимок JSON содержит документы и их токены. При загрузке `rank-bm25` восстанавливает скоринг по сохранённым токенам. [Реализация rank-bm25](https://github.com/dorianbrown/rank_bm25)

Оба поиска поддерживают фильтры по языку и категории. По умолчанию гибридный поиск берёт до 20 кандидатов из каждого канала и выдаёт 5. Reciprocal Rank Fusion суммирует для каждого UUID `1 / (60 + rank)` по каналам, где он найден. Ранги начинаются с 1, UUID учитывается в каждом канале один раз, а при равных значениях RRF порядок определяется UUID. В результате доступны итоговый балл и оба исходных ранга. [Статья о RRF](https://doi.org/10.1145/1571941.1572114)

## Сборка и защита контрольной выборки

1. `build_indexes` читает снимок `knowledge_base` в одной SQLAlchemy-сессии. Для новых индексов используются строки с `source_split=train`. Отдельный файл test предоставляет UUID и SHA-256 нормализованных новостей и эталонов.
2. Корпус отклоняется, если находит совпадающий UUID или текст. Сверка охватывает и случай, когда эталон в одном наборе встречается как новость в другом. Затем создаются BM25 и версия Qdrant с теми же документами.
3. Перед публикацией проверяются размерность и метрика коллекции, число и точное множество UUID, payload, контрольная сумма BM25 и отсутствие контрольных UUID и хешей в обоих хранилищах. После этих проверок атомарно заменяется `active.json`. Сбой оставляет прежнюю версию доступной.
4. При повторе с тем же корпусом, моделью и контрольным набором активная версия проверяется и переиспользуется. Если набор test изменился, поиск отклоняет устаревший снимок до переиндексации. Поиск также исключает точное нормализованное совпадение с текущим запросом.

Снимки содержат тексты XSum. Храните их локально в исключённом из Git `data/indexes/`. При выборе другого каталога храните его за пределами отслеживаемых файлов. Проверка хешей ловит точные совпадения после нормализации. Пересказ одной новости другими словами может пройти эту проверку.

## Передача в Summarizer

`await retriever.enrich_state(state)` возвращает копию `AgentState` с `rag_context` и UUID выдачи. Число предложений и длина эталона наиболее похожей статьи выбирают одну подсказку из закрытого списка структур. В промпт попадает максимум одна подсказка до 160 символов в JSON. UUID, текст учебной новости и слова её эталона остаются вне промпта. Summarizer проверяет значение по закрытому списку.

В промпте `news` остаётся текстом пользователя и единственным источником фактов. `style_examples` задаёт форму, например кратко изложить главное в одном предложении. Реальный CLI вызывает RAG только в `full` и сохраняет UUID найденных документов и число переданных подсказок. [Шаблон Summarizer](../backend/agents/prompts/summarizer.txt) · [Диагностика качества](./experiments.md)

## Запуск из Windows PowerShell

Установите группу `rag` в существующее окружение Poetry. Windows и Linux используют официальный CPU-индекс PyTorch. Для macOS Apple Silicon lock выбирает wheel из PyPI. Фактический прогон выполнен на Windows. Для выбранной версии PyTorch wheel macOS Intel не опубликован. [Файлы PyTorch 2.9.1](https://pypi.org/project/torch/2.9.1/#files)

```powershell
poetry install --with rag
$env:DATABASE_URL = 'sqlite+aiosqlite:///data/corpus-stage9-verified.sqlite3'
$env:QDRANT_MODE = 'local'
$env:OMP_NUM_THREADS = '4'
$env:MKL_NUM_THREADS = '4'
poetry run python -m scripts.build_indexes
poetry run python -m scripts.build_indexes
poetry run python -m scripts.build_indexes --verify-only
poetry run python -m scripts.search_indexes 'Rail passengers face disruption after a strike by train drivers' --language en
```

При первом построении модель загружается в `.cache/sentence-transformers`. После загрузки можно задать `EMBEDDING_LOCAL_FILES_ONLY=true`. В отчёте индексации проверяйте `bm25_count`, `qdrant_count`, `ids_match`, `test_overlaps` и `errors`. При повторном запуске с теми же входами ожидается `reused=true`. Поиск выводит UUID, ID XSum, ранги, оценки, короткие фрагменты и время после открытия индексов и разогрева модели. Аргумент `--mode` принимает `qdrant`, `bm25`, `rrf` или `all`.

Быстрые тесты подставляют модель эмбеддингов и используют Qdrant local. Отдельный тест проверяет настоящие MiniLM и Qdrant с уже скачанными весами. Команда ниже включает его без доступа к сети.

```powershell
$env:RUN_LIVE_EMBEDDINGS = '1'
$env:HF_HUB_OFFLINE = '1'
poetry run pytest --cov=backend
```

## Межъязыковой поиск в пользовательской суммаризации

Пользовательский API и CLI сначала ищут по BM25 и Qdrant на языке исходной новости. Если кандидатов меньше `top_k`, оставшиеся места может заполнить поиск Qdrant по другим языкам с cosine от 0,30. Категория и исключение исходного текста остаются в силе. Эмбеддинг запроса переиспользуется. Найденные пары сверяются с holdout. В промпт передаётся только одна нейтральная подсказка о форме.

В ответе `rag_search_mode` и на странице результата видны `same_language`, `cross_language`, `mixed`, `unfiltered` или `no_results`. Если проверенный индекс не дал кандидатов, `full` продолжает проверку резюме без подсказки. Недоступность или повреждение индекса остаются ошибкой поиска. Воспроизводимая оценка с зафиксированным снимком сохраняет прежний поиск по языку.

На реальном снимке из 1000 учебных XSum-документов запрос о казанской библиотеке дал 0 совпадений при русском фильтре и 5 английских документов при межъязыковом поиске. Cosine составил 0,309–0,352, пересечений с 200 test-документами не было. Темы выдачи включали открытие гостиниц и цифровое школьное обучение, прямых совпадений по библиотеке среди пяти результатов не обнаружено. Порог ограничивает возврат слабых совпадений, но его пригодность для межъязыкового поиска на других запросах отдельно не измерялась.
